# تخطيط موديول التوصيل delivery (v1 — مسودة)

> P5. من تجهيز الطلب حتى إثبات التسليم.
>
> **الحالة: مُنفذ ومُختبر** (مركبات + رحلات + محطات + إثبات/فشل + `DeliveryFlowTest` أخضر). إدارة الرحلات SUPER_ADMIN (قيد SecurityConfig).

## 1. الرحلات والمحطات

- `delivery_trips`: سائق + عربية + تاريخ + مسار (محطات مرتبة).
- `trip_stops`: طلب + ترتيب + نافذة زمنية + حالة (pending → delivered/failed) + إثبات (توقيع/صورة).
- الفشل: سبب من قائمة (مغلق/رفض/عنوان خطأ) → إعادة جدولة تلقائية.

## 2. المركبات

`vehicles`: فرع + نوع + سعة + حالة + صيانة (تنبيه مواعيد — nice).

## 3. التنسيق مع المخزن

الطلب لا يدخل رحلة إلا بعد تأكيد التجهيز من الفرع؛ التسليم الناجح يقفل الطلب (`delivered`) ويفتح باب التقييم.

## 4. Must / Nice

**Must**: رحلات + محطات + إثبات + أسباب فشل + إعادة جدولة.
**Nice**: تتبع GPS حي للعميل، تحسين المسار تلقائياً، تقييم السائق.

## 5. قرارات محسومة (من النقاش)

1. **رسوم التوصيل**: حسب المنطقة/المحافظة (جدول مناطق بأسعار).
2. **التطليع (وليس تركيب)**: عمال يشيلوا المرتبة للدور — الأول والثاني 50 ج.م، +50 لكل دور زيادة (الثالث 100، الرابع 150...).
