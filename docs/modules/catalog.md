# تخطيط موديول الكتالوج (v1 — مسودة للنقاش)

> يغطي: الأصناف، البراندات، المقاسات، الصفات، القوالب، التقييم والمراجعات، والـ APIs.
>
> **الحالة: مُنفذ ومُختبر** (quick-create + search/featured/compare + reviews + Q&A + brands + quiz + variant-attrs + bought-together + `CatalogExtraFlowTest` أخضر).
> المبدأ: أي نوع جديد = داتا من الداشبورد، بدون كود.

## 1. شجرة الأصناف المقترحة (seed أولي)

| الصنف | الأنواع تحته | ملاحظات |
|---|---|---|
| مراتب | سوست متصلة، سوست منفصلة (بوكيت)، إسفنج مضغوط، لاتكس، ميموري فوم، طبية | الصنف الأهم — أكتر صفات ومقاسات |
| مخدات | فايبر، لاتكس، ميموري فوم، مخدة طويلة، خدادية، مسند ظهر، مسند رقبة، وسادة نوم طبية | كل نوع preset مستقل بصفاته |
| كفرات مراتب | قطن، وتربروف، فايبر، لاتكس | تُستخدم في البندل (مرتبة + كفر) |
| (مستقبلاً) | مصاحف، مصليات، مفروشات | الهيكل يستوعبها بدون تعديل |

## 2. سياسة الباركود والتعريف

- منتجات كتير **ملهاش باركود** ← الباركود **اختياري** (nullable أصلاً في `product_variants` — يُعتمد رسمياً).
- المعرف الإلزامي هو **SKU** فريد لكل متغير، بتوليد تلقائي: `{SLUG}-{W}X{L}X{H}` (مثال: `SERTA-120X195X25`).
- البحث والبيع يتم بـ SKU أو الاسم أو الـ slug؛ الباركود يُستخدم فقط عند وجوده (سكانر الكاشير/POS).

## 3. الصفات (EAV) لكل صنف

صفات مشتركة: البراند، الضمان (سنوات)، بلد الصنع، الخامة الأساسية.
صفات المراتب: نوع السوست، الارتفاع (سم)، الصلابة (طري/وسط/صلب)، الطبقات، قدرة التحمل (كجم).
صفات المخدات: النوع (فايبر/لاتكس/ميموري)، الارتفاع، المقاس (50×70...)، قابلية الغسيل.
صفات الكفرات: الخامة، المقاس المتوافق، وتربروف (نعم/لا)، سوستة (نعم/لا).
- الصفة تُعرّف مرة واحدة (`attribute_definitions`) وتُربط بأي صنف (`category_attributes` إجباري/اختياري).
- البراند حالياً حقل نصي على المنتج؛ **كيان مستقل للبراندات (nice-to-have)** لاحقاً (شعار، وصف، ترتيب).

## 4. المقاسات القياسية (seed كـ presets)

مراتب (سم): 90×195، 100×195، 120×195، 150×195، 160×195، 180×195 — بارتفاعات 20/25/30.
مخدات: 50×70، 50×80، طويلة 50×120، خدادية 45×45.
كل (موديل × مقاس) = variant بسكو وسعر مستقل. إنشاء مقاس جديد = quick-create من القالب بخطوة واحدة (8 في arch.md).

## 5. التقييم والمراجعات (جديد — يُصمم الآن، يُنفذ في P2)

- `product_reviews (product_id, user_id, rating 1-5, title, body, verified_purchase, status, helpful_count)`.
- العميل يقيّم فقط منتج اشتراه فعلاً (`verified_purchase` من order_items) — مراجعات الضيوف اختيارية (قرار مفتوح).
- ملخص التقييم (المتوسط + العدد) يُحسب ويُخزن مؤقتاً على المنتج أو view — لا يُحسب live مع كل طلب.
- APIs: `GET /catalog/public/products/{slug}/reviews` (عام)، `POST /portal/reviews` (عميل)، `PUT /crm/reviews/{id}/moderate` (إدارة: قبول/رفض).
- Nice-to-have: صور مع المراجعة، تصويت "مفيد"، أسئلة وأجوبة Q&A.

## 6. الـ APIs (موجود + مخطط)

موجود: CRUD منتجات/أصناف/صفات/بريسِت + from-preset + تصفح عام.
مخطط P2: `quick-create` (8)، reviews الثلاثة أعلاه، `GET /catalog/public/products/search` بفلاتر الصفات (خامة/صلابة/مقاس/سعر).

## 7. Must-have مقابل Nice-to-have (تمييز السيستم)

**Must-have P2**: الشجرة أعلاه + seed البراندات والمقاسات + باركود اختياري + بحث بفلاتر + تقييم أساسي + quick-create.
**Nice-to-have (تميّز)**: كيان براندات مستقل، مقارنة منتجات (compare)، "اشترى معه" (من order_items لاحقاً)، Q&A، صور مراجعات، تنبيه "رجع للمخزن" للمفضلة، ترشيح Quiz (9) مبني على نفس الصفات.

## 8. أسئلة مفتوحة للنقاش

1. البراند: نص حر الآن أم كيان مستقل من P2؟
2. المراجعات: مشترين فقط أم أي زائر؟
3. المقاسات: نلتزم بالجدول أعلاه أم نضيف (200 طول، أطفال)؟
4. الكفرات تُباع منفصلة فقط أم بندل إجباري مع المرتبة؟
